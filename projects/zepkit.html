ZepKit

Multilingual semantic search for quick-commerce. Search in Hindi, Tamil, Bengali, Hinglish, English — with typos, slang, and natural language — and find the right product at your nearest dark store.

Source Code
Node.js Kafka (KRaft) TypeSense Redis MongoDB Ollama bge-m3 Gemma 3

The Problem

Plain keyword search breaks the moment the shopper and the catalog disagree on words. An Indian grocery shopper might type aloo, potato, or the same word in Tamil, Bengali, or Devanagari script. They might say "paneer butter masala banana hai" and expect ingredient suggestions. Existing search engines don't handle this out of the box.

ZepKit solves this with hybrid search (meaning + keywords together) and a 14-language tag net per product, so search just works regardless of language or script.

How Data Flows

Write Path (Admin adds a product)

Step 1 — Accept

POST /products assigns an _id, publishes product.created to Kafka, returns 202 Accepted. The API is done — no waiting for enrichment.

Step 2 — Enrich

The Kafka worker picks up the event. It generates 14-language tags (rule-first dictionary + Gemma 3 fallback), computes a bge-m3 embedding (1024-dim multilingual vector), and runs guardTags() content moderation.

Step 3 — Fan-out

The worker upserts into MongoDB (truth), TypeSense (search index with store_ids), and Redis (cache). Kafka offset is committed only after all three succeed. Idempotent upserts make retries safe.

Read Path (User searches)

Step 1 — Cache + Intent

Check Redis for cached results. Run recipe detection: KB dictionary for known dishes (instant), Gemma 3 LLM fallback for novel ones. Parse price filters from natural language (amul doodh 60 se kam → milk under 60).

Step 2 — Hybrid Search

Embed the query with bge-m3 (cached). Run TypeSense hybrid search: BM25 keyword match on title, tags, aliases + vector k-NN — filtered by store_ids for the user's pincode.

Step 3 — Demand Signal

If no keyword matched and the nearest vector is far, flag it as missed. This surfaces to the admin dashboard as a demand signal — close the loop by mapping it to a product.

Why These Choices

DecisionWhyTradeoff
TypeSense for hybrid search BM25 + vector k-NN + typo tolerance in a single hop. No need to stitch Elasticsearch + a separate vector DB. Fewer heavy analytics than Elasticsearch. Index lives in RAM. Fine for search-first at this scale.
Kafka as ingestion buffer Decouples write API from three stores. Replay, fan-out, DLQ for free. Demonstrates event-driven design. Heavier than this catalog strictly needs. At low write volume, direct writes would work. Here for the pattern.
Ollama (local models) bge-m3 is genuinely multilingual (core of cross-language search). Gemma 3 4B generates tags. Zero API costs, runs offline. Slow on CPU (~5-10s for tags). 4B model doesn't know every brand. That's why tags are rule-first with LLM as optional enrich.
Rule-first 14-language tags Curated dictionary + Devanagari-to-script transliteration. Instant, deterministic, no LLM latency for common products. Transliteration is phonetic, not translation (Marathi ~ Hindi script). Upgrade path: AI4Bharat IndicXlit.
MongoDB = source of truth Everything else (TypeSense, Redis) rebuilds from Mongo. reindex replays Mongo → search + cache. Index corruption is recoverable. Extra write on the ingest path. Worth it for recoverability.
Browser Speech API for voice Zero backend, zero latency. hi-IN continuous mode with live transcript. Blinkit-style overlay UX. Browser-dependent (Chrome best). No server-side fallback. Acceptable for a demo.

Key Engineering Details

  • Hybrid search fusion — TypeSense runs BM25 keyword search and vector k-NN in a single query, fused internally. No separate re-ranking step needed.
  • Store-scoped filtering — Each product has a store_ids array. Search filters by the user's resolved store, so results only show in-stock items at their nearest dark store.
  • Exactly-once semantics (practical) — Kafka offset committed only after all three stores succeed. Idempotent upserts mean retries don't duplicate. 3 failures → DLQ for manual inspection.
  • Content safety gate — guardTags() is fail-closed: veg/non-veg correctness, no slurs, clean data. Runs before any tag is persisted.
  • Recipe detection (two-tier) — Instant KB dictionary (5 common dishes) → Gemma 3 LLM fallback for novel dishes. Hinglish trigger phrases like "banana hai" activate it. Veg-only, fail-closed.
  • Search analytics loop — Every search, click, and add-to-cart is logged. Dashboard shows CTR, zero-result rate, searches by script, per-day trends. Missed queries surface as demand signals.
